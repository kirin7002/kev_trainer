# Kev 原生微调与固定评测

## 本轮目标

保留单服务、文件存储及 Kev 原生决策结构。每个新实验冻结模型、问题定义、阈值、数据划分与评测规则；先建立基线，再在相同样本上对比候选。外部预测始终标记为用户导入，不冒充真实训练。

## 执行清单

- [x] 保存实验级训练、验证、测试快照及可校验的评测协议。
- [x] 分开验证集与最终测试集的基线、候选及报告；基线不可被替换。
- [x] 验证集选定候选后锁定，才开放最终测试；最终测试不能用于继续选模型。
- [x] 导出 Kev 原生 Noul JSONL、固定版本与训练命令清单，不包含最终测试数据。
- [x] 页面提供阶段切换、基线状态、候选锁定及训练包下载。
- [x] 覆盖协议错配、数据变更、负标签、候选锁定、重启恢复和旧实验兼容测试。
- [x] 完整 pytest、服务健康检查及页面检查。

本轮还增加独立业务范围、模型输入中的场景信息、可变问题数量，以及分业务指标和划分覆盖警告。已完成项均为离线开发能力；真实 GPU 推理与训练仍是下述外部前提及后续实现。

## 实际训练的外部前提

- GPU 机器、运行环境及权限由用户后续配置；本轮不连接 SSH、WSL2 或远程训练服务。
- 在接入机器后验证 Kev 固定版本安装、基线推理、短训练、检查点重载、候选推理与最终测试。
- 训练完成、参数更新与效果改善必须分别取得真实证据；接口和假进程测试不能替代 GPU 验收。

## 数据约定

标签数组表示完整标注，未列出的已定义标签为否；Noul 格式仅对当前样本明确提供布尔标签的问题训练和评测，未询问的问题不视为否，因此允许混合不同问题数量的业务场景。问题定义从训练数据或用户配置建立，不从最终测试集推断。模型与问题、阈值、数据、评测规则任一改变都需要新实验、新基线。
